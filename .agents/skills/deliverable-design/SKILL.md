# Design deliverables
Read docs/deliverable-design.md and the agent register/workflow catalog. Identify the business outcome before choosing format. Ask only unresolved questions about owner, consumer, format, evidence and acceptance.
Draft templates/deliverable.json for each material output. Link outputs to workflow steps and responsible agents. Distinguish producer from verifier, acceptance authority and recipient. Specify draft/review/release states, version, evidence and authorized access.
Run the offline validator; then evaluate actual content against acceptance criteria. Structural validation does not prove accuracy, acceptance or delivery. Never mark a deliverable accepted or delivered merely because a file exists. Preserve prior versions and record review feedback.
